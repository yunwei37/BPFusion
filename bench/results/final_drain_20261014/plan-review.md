## Source and ownership semantics

Inspection used live main f232b475a4663731636067c0d2a95fc52603cd82, executor/vllm_graph.cu, executor/io_uring_tcp.h, bpf/fusion.bpf.c, the queue definitions/loader, native epoll path, Makefile/backend linkage, docs/evaluation.md, finding0052, and the declared TEMP plan/adapters/rebuild/analysis recipes.

1. **The counters have matching units.** Control is zero-initialized at vllm_graph.cu:202-209; its unsigned seen counts FIFO model admissions and retired counts the completed FIFO prefix (81-84,109-125). IoState initializes unsigned seen and next_final to zero (io_uring_tcp.h:85-94); it claims the same page llm_head in original sequence order (202-220). A reservation advances the low unsigned 32-bit llm_admission head, with the upper bitmap retaining physical ownership (fusion.bpf.c:82-97). next_final advances once per complete final SEND or abort CQ (152-160), including rejected requests. These are admitted-request counts/sequences, not token, CQ, or graph counts. Equality/inequality is appropriate to the existing modulo counters; the proposal introduces no ordered rollover comparison. Finite wrap/reuse qualification does not establish behavior after 2^32 requests.
2. **BF_DONE does not free TX ownership.** The model marks its completed FIFO slots BF_DONE and clears only its local phase. uring_recycle binds to the registered owning ring, checks the final SEND/abort tag and exact completion result, requires BF_DONE, then sets BF_FREE and clears the admission bitmap bit (fusion.bpf.c:428-446). This is a distinct kernel completion/recycle step. GPU next_final changes only after consuming the CQ and retiring the matching active/tagged IoRequest. BPF recycling may precede GPU CQ observation: this does not grant premature GPU request reuse because io_progress drains CQ first and an IoRequest remains active until that drain; model phases are separately guarded.
3. **The intervention matches the stated narrow mechanism.** It runs after io_progress and only when Control.retired==Control.seen. It delays new model admission until next_final equals the retired model prefix and SQ head equals tail. Thus it waits for completed responses' final-send/abort CQ processing and existing published submissions, not TCP ACK, all accepts/receives, or all network activity. It remains an all-model-idle gate: when admitted inference is unfinished, existing admission/selection behavior is unchanged, including the ability to admit other requests. Reduced graph count would support the aggregate batching/scheduling prediction, not identify a single CQ as the causal mediator.
4. **No circular model/TX dependency was found for the proposed path.** At the idle gate every already-model-admitted request in the waited prefix has finished. io_progress can claim and deliver its existing replies, including rejection/abort handling. Final sends remain admission-ordered (io_uring_tcp.h:259-278); per-peer reply linkage serializes pipelines (214-219,238), and final CQ retirement advances that peer's queue. Fresh VALIDATING requests can be claimed by I/O, but require model validation before response emission; they are outside the completed prefix being awaited. The gate does not wait for their final completion before admitting them. Recycled physical slots retain the active/tag and phase guards. Actual qualification must still exercise wrap, rejection, pipeline, half-close, and peer reuse.
5. **Backpressure is a real cost, not a missing proof silently supplied by this review.** A backpressured earlier final SEND can delay next_final and globally stall fresh admission even when other peers are ready. The proposal explicitly retains that boundary. No finite test or favorable average establishes fairness, bounded tail latency, or arbitrary-peer progress. This admission is valid only with that scope; it does not justify general/default promotion on the planned metrics alone.
6. **Stop remains reachable and memory lifetime is coherent.** dispatch checks page stop_ns before each gate iteration (76). Stop/signal breaks the existing host kernel-loop wait; the host sets page stop, synchronizes the model root/children, marks model_quiesced, then launches the existing shutdown-only io_network worker and drains (vllm_graph.cu:268-276; io_uring_tcp.h:391-406,493-499). The candidate adds no steady network CTA/worker. Mapping registrations, I/O state and buffers remain until that worker stream has completed; only then are links/ring/state/registrations released (505-527), with page unregister later. The review finds no new lifetime/stop hazard, while terminal shutdown counters and raw lifecycle output remain required evidence.

## Same-process ordinary round authentication

The split is scientifically useful and executable: short_serving.py contains only ((1,8),), transfer_serving.py contains ((1,1),(64,1),(64,8)). Thus each primary short process contains exactly eight sequential c1/gen1 warmups and its measured gen1/c8 cell, not hidden long-output computations. Warmups use request/response synchronously on one connection (203-206). A gen1 final reply requires completed model work, so no second warmup can share its graph round. Graph capture occurs before the C++ Control allocation; Control.launches increments only for successful actual device model rounds (167-174). The printed device_graph_launches counter reports that field. Each valid gen1 request emits once; no rejection appears in ordinary data. Therefore total counter minus eight authenticates the measured aggregate model rounds in the very same untraced primary process.

analysis.py short_rounds also requires admitted==retired==count+8, no errors/trace overflows, complete gen1 outputs and measured rounds in [ceil(count/8),count]. This remains an aggregate, not observed batch membership, GPU time, or proof of universal mediation. The plan correctly requires client TTFT and round-count judgments separately: fewer rounds without a client benefit cannot replace the primary effect, and a client benefit without fewer rounds does not support the proposed batching explanation.
