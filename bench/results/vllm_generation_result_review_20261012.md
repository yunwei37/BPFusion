## Actual optimized body, head and sampling seam

Installed ModelCudaGraphManager stores model output in its persistent
hidden_states buffer and returns the active FULL prefix. The hook first
calls the original FULL body, saves its output, and captures the official
head on manager.hidden_states[:batch] with active-row indices. These are
real changing model outputs, not constant copied hidden states.

Qwen2ForCausalLM.compute_logits calls its actual logits processor and LM
head. Installed gumbel_sample supplies the official reduction/gather output
IDs. Its temp0 branch is plain argmax; seeds and request mapping do not add
noise when temperature is zero. The prototype captures these official
operations with temperature0 and no penalties/logit processing. It is
equivalent for this deliberately narrow request subset, not a generic
replacement for all upstream sampling policies.

The body is the actual retained manager.graphs[desc] FULL graph, and the
head is an actual Torch CUDA graph. Native construction adds both as child
graph nodes with an explicit body→head dependency. The combined executable
and GPU parent both have device-launch capability and are uploaded before
the run. This directly resolves the earlier mirror-parent limitation,
which had not needed to tail-launch itself.

Each device parent waits at the tail completion seam after its child
execution environment finishes, then consumes sampled IDs, publishes
the next input/metadata and launches the next body+head child. Explicit
dependency and tail join prevent reading head samples before the body/head
has completed. One native host graph launch and final stream synchronization

These counts apply to the native loop only. Official prefill, initialization,
graph/head warmup/capture, initial FULL replay, reference loading and the

## KV ownership and metadata advancement

The actual installed InputBuffers use int32 input IDs/sequence lengths and
int64 positions, matching native pointer types. Installed BlockTables use

No independent allocator, guessed physical IDs, early KV release or CPU

ungenerated future outputs computed.

slot mappings and the original FULL hidden output. Its finally block restores
all four prepared tensor ranges and the saved official hidden output before

selected as future-write targets by the inspected loop.
